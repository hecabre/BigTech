# Plan principal — Amazon SDE Graduate

## Meta

Llegar a mayo de 2027 con preparación demostrable para procesos SDE Graduate/New Grad, priorizando Amazon:

- fundamentos de estructuras de datos y algoritmos;
- capacidad de resolver y explicar un Online Assessment;
- historias STAR ligadas a los Leadership Principles;
- fundamentos de computación, bases de datos, redes y diseño de sistemas;
- un proyecto desplegado en AWS que pueda explicarse con decisiones, métricas y costos;
- CV, LinkedIn, portafolio y tracker de postulaciones activos.

## Orden de prioridad

1. **Esencial:** tarea principal de la fase, entregable semanal y preparación de procesos activos.
2. **Importante:** práctica de entrevista marcada en el calendario.
3. **Opcional:** LeetCode adicional, lecturas extra y laboratorios no necesarios para el cierre semanal.

Los problemas de algoritmos ya asignados en el calendario forman parte del camino base hacia SDE. Cualquier problema adicional realizado en tiempo libre se registra como **LeetCode extra** y nunca desplaza lo esencial.

## Definición de semana completa

Una semana se considera completa cuando:

- se obtuvo el resultado principal de la semana;
- se registró evidencia o una nota explicable;
- se anotó al menos un error o aprendizaje;
- se completó la revisión del viernes;
- se definió una única prioridad para el lunes siguiente.

No es necesario completar todos los extras para marcar una semana como terminada.

## Flujo semanal

### Lunes — trabajo profundo

- Leer el objetivo en el [calendario](01-CALENDARIO_SEMANAL_BIG_TECH_AWS.md).
- Copiar las tareas relevantes a la nota semanal.
- Definir el entregable observable, no solo “estudiar”.

### Martes a jueves — ejecución corta

- Una sesión enfocada de 30–60 minutos.
- Registrar errores inmediatamente en [errores AWS](Recursos/Registro-de-errores-AWS.md) o [errores de algoritmos](Recursos/Registro-de-errores-algoritmos.md).
- Si sobra tiempo, elegir un ejercicio de la sección opcional.

### Viernes — cierre

- Actualizar el [tablero de progreso](02-TABLERO-DE-PROGRESO.md).
- Completar la retrospectiva de la nota semanal.
- Registrar postulaciones y seguimientos en el [tracker](Recursos/Tracker-de-postulaciones.md).
- Elegir una sola prioridad para el próximo lunes.

## Política de recuperación

- No duplicar carga la semana siguiente.
- Mover solo el entregable esencial pendiente.
- Eliminar primero los extras de LeetCode.
- Si hubo menos de seis horas de sueño, hacer repaso en lugar de problema nuevo.
- Si existe un proceso de selección activo, sus fechas tienen prioridad sobre certificaciones y calendario.

## Indicadores de preparación

| Área        | Evidencia esperada                                                          |
| ----------- | --------------------------------------------------------------------------- |
| Coding      | Dos problemas en 70 minutos, con casos límite y complejidad explicados      |
| Behavioral  | Diez historias STAR reutilizables y con resultados medibles                 |
| Fundamentos | POO, SQL, SO, redes y sistemas distribuidos explicables                     |
| AWS         | Arquitectura desplegada, observable, reproducible y con costos documentados |
| Búsqueda    | Perfil listo, tracker actualizado y postulaciones constantes                |
